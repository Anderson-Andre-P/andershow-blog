# Introduction to consuming APIs

APIs, or Application Programming Interfaces, are sets of rules and protocols that let different systems talk to each other. In web development, APIs let us access and interact with resources or features from external services, such as data, authentication, third-party services and much more.

In React JS, the main idea is to use APIs to fetch and send data dynamically, so our app can communicate with the outside world and become more powerful and interactive for users.

# Ways to consume APIs with React JS

There are several ways to consume APIs in React JS apps. Let's look at two of the most common:

**A) Native Fetch API:**

The Fetch API is a modern, native JavaScript API for making HTTP requests. We can use it to fetch data from an external API. For example, suppose we want to show information about a book from a books API:

```jsx
fetch('https://api.example.com/books/123')
  .then((response) => response.json())
  .then((data) => {
    // Use the returned data to update the component state
    this.setState({ book: data })
  })
  .catch((error) => {
    // Handle network or processing errors here
    console.error('Error:', error)
  })
```

**B) Axios:**

Axios is a popular JavaScript library for making HTTP requests. Many developers prefer it for its simplicity and support for features like request cancellation and interceptors. Here's an example of Axios consuming the same books API:

```jsx
import axios from 'axios'

axios
  .get('https://api.example.com/books/123')
  .then((response) => {
    // Use the returned data to update the component state
    this.setState({ book: response.data })
  })
  .catch((error) => {
    // Handle network or processing errors here
    console.error('Error:', error)
  })
```

# Handling responses and errors

When consuming APIs, we usually receive responses as JSON. It's important to handle these responses properly. If the server returns invalid data or there's a network problem, we need to handle it so the app doesn't break. Promises or async/await make this easier.

For example, suppose we want to show a list of blog posts:

```jsx
async componentDidMount() {
  try {
    const response = await fetch('https://api.example.com/posts');
    if (!response.ok) {
      throw new Error('Error fetching data');
    }
    const data = await response.json();
    this.setState({ posts: data });
  } catch (error) {
    console.error('Error:', error.message);
  }
}
```

# Authentication and authorization

In many cases, we need to authenticate our API calls to access protected resources. For that, we can use authentication tokens such as JSON Web Tokens (JWT). Authentication makes sure only authorized users can access certain parts of the API. When consuming APIs that require authentication, we need to include the right headers in our requests:

```jsx
axios.get('https://api.example.com/protected-data', {
  headers: {
    Authorization: 'Bearer YOUR_JWT_TOKEN',
  },
})
```

# Component state and lifecycle

When consuming APIs with React JS, we need to understand the component lifecycle. The `componentDidMount()` method is a common place for API calls, since it runs after the component renders. We should also use `state` to store the data we receive and update the UI as needed.

```jsx
class MyComponent extends React.Component {
  state = {
    data: null,
  }

  async componentDidMount() {
    try {
      const response = await fetch('https://api.example.com/data')
      const data = await response.json()
      this.setState({ data })
    } catch (error) {
      console.error('Error:', error.message)
    }
  }

  render() {
    const { data } = this.state

    if (!data) {
      return <div>Loading...</div>
    }

    // Render the received data here
    return <div>{data.name}</div>
  }
}
```
